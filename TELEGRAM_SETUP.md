# Telegram-бот модерації — налаштування

Бот надсилає нові й повторні заявки на модерацію в **закритий** робочий чат модераторів із кнопками
«✅ Підтвердити» / «❌ Відхилити». Рішення виконує той самий сервіс модерації, що й адмінка
(`properties/moderation.py`): перевірка прав, актуальної версії заявки, обов'язкова причина відхилення,
запис в історію модерації. Код: `properties/telegram_bot.py`, команда `telegram_moderation_bot`.

> Стан: код і автотести (імітація Telegram API) готові. Реальна перевірка з ботом **не виконувалась** —
> потрібні токен і чат (кроки нижче).

## 1. Створити бота

1. У Telegram відкрийте **@BotFather** → `/newbot` → назва (напр. «mobi Home Модерація») → username (закінчується на `bot`).
2. Скопіюйте **токен** (`123456789:AA…`). Це секрет: лише в `.env` на сервері, не в Git, не в чати.
3. `/setprivacy` → оберіть бота → **Disable** (щоб бот бачив відповіді з причиною відхилення в групі).
4. `/setjoingroups` → **Enable** (додати в групу), після додавання можна знову вимкнути.

Якщо для входу через Telegram на сайті вже є бот (`TELEGRAM_BOT_TOKEN`), можна використати його ж.

## 2. Закрита група модераторів

1. Створіть **приватну** групу (напр. «mobi Home — модерація»), додайте бота й модераторів.
2. Дізнайтесь **chat ID** групи: напишіть у групі будь-яке повідомлення, потім на своєму комп'ютері:
   ```bash
   curl -s "https://api.telegram.org/bot<ТОКЕН>/getUpdates" | python3 -m json.tool | grep -A3 '"chat"'
   ```
   ID групи — від'ємне число (для супергруп починається з `-100…`).

## 3. Налаштування `.env`

```ini
TELEGRAM_BOT_ENABLED=True
TELEGRAM_BOT_TOKEN=<токен від BotFather>
TELEGRAM_MODERATION_CHAT_ID=<chat ID групи, напр. -1001234567890>
SITE_URL=https://<ваш-домен>      # для кнопки «Відкрити оголошення в адмінці» (localhost/http — кнопки немає)
```

Без `TELEGRAM_BOT_ENABLED=True` або без чату бот нічого не надсилає (сайт працює як звичайно).

## 4. Прив'язати модераторів

Права перевіряються за **числовим Telegram user ID** (не @username, його можна змінити).

1. Кожен модератор дізнається свій ID (напр. бот **@userinfobot** → `/start`).
2. Акаунт модератора на сайті створює адміністратор (адмінка → Користувачі → Додати; пароль задає модератор).
3. Група прав і прив'язка:
   ```bash
   python manage.py setup_moderators                                # група «Модератори» (ідемпотентно)
   python manage.py setup_moderators --add olena --telegram olena=123456789
   ```
   Або в адмінці: Профілі користувачів → `Telegram ID`.

Кнопки спрацьовують лише якщо: повідомлення з дозволеного чату; Telegram ID прив'язаний до **активного**
акаунта персоналу з правом модерації (група «Модератори» або суперкористувач); заявка ще «На перевірці»
і її версія не змінилась. Повторні натискання та застарілі повідомлення відхиляються з поясненням.

## 5. Запуск і перевірка (локально)

```bash
set -a; . ./.env.sandbox; set +a          # або інший .env з TELEGRAM_* та тестовим чатом
python manage.py telegram_moderation_bot --once    # один цикл: перевіряє токен і доступ до Telegram
python manage.py telegram_moderation_bot           # постійна робота (Ctrl+C — зупинка)
```

Перевірка: створіть оголошення на сайті (або «Надіслати на модерацію») → у групі з'являється заявка →
«Підтвердити» → в адмінці статус «Схвалено», в «Історії модерації» — запис із джерелом Telegram.
«Відхилити» → бот просить причину → відповідайте **на повідомлення бота** → статус «Відхилено», власник бачить причину.

Якщо Telegram був недоступний, повідомлення надішлеться повторно (до 5 спроб) при наступному циклі бота.

**Фото заявки.** Бот надсилає справжні фото власника з диска (Storage API, multipart) — публічна адреса сайту не потрібна:
- 1 фото — `sendPhoto`: фото + підпис + кнопки в одному повідомленні;
- 2–10 фото — альбом `sendMediaGroup` (головне фото першим), далі окреме повідомлення з даними й кнопками у відповідь на альбом;
- понад 10 — кілька альбомів по 10 (залишок з 1 фото — `sendPhoto`);
- відсутні, пошкоджені, понад 10 МБ або з недопустимими пропорціями файли пропускаються; якщо Telegram відхилив альбом —
  фото надсилаються поодинці; у будь-якому разі повідомлення з кнопками надходить;
- фото надсилаються один раз на версію заявки (повторна спроба — лише повідомлення з кнопками);
- приватні звіти інспекторів і документи не надсилаються ніколи.

Бот перевірено в реальній приватній групі з demo-базою й **підтверджено замовником (25.11)**; окремого підтвердження кожного сценарію з фото (1 фото, альбом, понад 10 фото, пошкоджений файл) не зафіксовано — позначено окремо.

## 6. Production (systemd)

```bash
sudo cp deploy/telegram-bot.service /etc/systemd/system/mobihome-telegram-bot.service
sudo systemctl daemon-reload && sudo systemctl enable --now mobihome-telegram-bot
journalctl -u mobihome-telegram-bot -f
```

Бот працює через **long polling** (вебхук і відкритий порт не потрібні). Якщо раніше для бота встановлювали
webhook, видаліть його: `curl -s "https://api.telegram.org/bot<ТОКЕН>/deleteWebhook"`.

## Безпека

- Токен — лише в `.env` (права 600); у логах і помилках не друкується.
- Користувацький текст оголошення екранується (HTML); у повідомлення не потрапляють email і телефон власника.
- `callback_data` (номер оголошення й версія) не є довіреними — усе перевіряється на сервері.
